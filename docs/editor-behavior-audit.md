# Markdown editing conventions and oracle opportunities

Current implementation status and priorities are in [editor-research-next-steps.md](editor-research-next-steps.md). The catalog below retains the original research snapshot.

Research date: 2026-11-18. This catalog compares Studio's source editor with four public implementations. Its recommendations are proposals, not new oracle laws. Rendering standards decide whether emitted Markdown has the intended meaning; editor conventions decide what a command should do to a selection. Those are separate questions.

The closest references are GitHub's textarea toolbar and Markdown All in One's source-editing commands. EasyMDE adds useful examples of context-aware code and list editing. CodeMirror's Markdown package provides parser-aware list and blockquote editing. Markdown All in One is a VS Code extension; its behavior must not be described as built into VS Code.

The user's already adopted choices remain fixed: literal marker-only content survives emphasis; unknown key strings return `null`; existing display formulas stay unchanged; numbered parents through nine digits get enough indentation for an actual sublist; Shift+Enter preserves closing fences; whitespace-only emphasis follows GitHub's empty-pair convention. Differences in another editor do not reopen those decisions.

## Behavior catalog

| Behavior | Reference evidence | Studio audit | Recommendation |
|---|---|---|---|
| Bold/italic on selected text | GitHub [style and trim rules](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L598); EasyMDE [`_toggleBlock`](https://github.com/Ionaru/easy-markdown-editor/blob/a48434196c8cfbfb2cae708390a26aed527cbf8c/src/js/easymde.js#L1324); All in One [`wrapRange`](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/formatting.ts#L470). | Selected text is wrapped, selected internal/external star markers toggle off, and the complementary style survives. | Preserve the adopted rule. Generate overlapping style combinations and sequences, not only plain words. |
| Surrounding whitespace | GitHub keeps selected leading/trailing whitespace outside markers. Run: selected ` word ` becomes ` **word** `. An all-space selection becomes ` ****`, caret inside the pair. | Nonempty content trims correctly. Whitespace-only selection was wrapped inside the markers at the audit snapshot; the GitHub convention is now adopted for repair. | Enforce the adopted GitHub rule across spaces, tabs and other supported whitespace. Do not describe it as a rule mandated by Markdown itself. |
| Bold/italic with a caret inside a word | GitHub [`expandSelectedText`](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L534) expands to a whitespace-delimited word. All in One [`styleByWrapping`](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/formatting.ts#L404) uses VS Code's word range. | Run: Bold at `wo|rd` produces `wo**|**rd`; GitHub produces `**wo|rd**`. | A useful candidate port. Decide word-boundary and caret behavior explicitly before replacing the currently adopted empty-pair rule. GitHub and VS Code use different definitions of a word. |
| Marker spelling | GitHub defaults to `**` bold and `_` italic. EasyMDE's removal path recognizes star and underscore emphasis. All in One has configurable bold/italic indicators. | Studio writes and recognizes star runs only. Run: selecting the text inside `_word_` and invoking Italic produces `_*word*_`. | Alternate-marker removal is a compatibility proposal, not a cross-editor consensus. Rendering both spellings does not automatically specify what a shortcut must remove. |
| Multiline emphasis | GitHub's bold style wraps the whole selection; its `multiline` option is used by other styles. Studio and some source editors instead operate per line. | Studio's per-nonblank-line behavior is already adopted and avoids wrapping across a blank paragraph boundary. | Keep Studio's adopted rule. Do not copy GitHub's output merely to match a reference implementation. Test blank paragraphs, mixed styles and CR/LF boundaries. |
| Inline code | GitHub's [code style](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L97) uses backticks for one line and a fence for multiple lines. EasyMDE [`toggleCodeBlock`](https://github.com/Ionaru/easy-markdown-editor/blob/a48434196c8cfbfb2cae708390a26aed527cbf8c/src/js/easymde.js#L449) chooses inline code for an ordinary single-line selection, but a fence for multiple lines or an empty caret at line start. All in One has a separate [`toggleCodeSpan`](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/formatting.ts#L40). | The formatter and toolbar offer fenced blocks, not an inline-code command. Run: selecting `word` with the code-block button creates a fenced block. This is correct for its existing label. | Add a separate inline-code command first. Keep the explicitly named code-block button predictable. A later combined command can be a deliberate UI choice. |
| Removing existing code formatting | EasyMDE identifies inline, fenced and indented code and can remove the relevant formatting. GitHub removes recognized wrapper text around its selection. All in One's command named `toggleCodeBlock` actually inserts a snippet; the name alone is not evidence of a toggle. | Studio's code-block command always wraps; repeated wrapping can create nested literal fences. | A code-block unwrap/toggle is useful but not as universal as inline-code support. Define partial selections, language info and caret-only behavior before porting. |
| Link label/target workflow | GitHub's [link style](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L103) distinguishes selected URL text from labels and selects the field to fill next. EasyMDE offers a configurable link prompt. | Studio already places selected words in the label and a selected lowercase HTTP(S) URL in the target, with the caret in the empty field. | Preserve the existing workflow. Generate URL paths, fragments, queries and Unicode deliberately. |
| URL pasted over selected text | All in One's [`paste`](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/formatting.ts#L337) turns a recognized clipboard URL into a link around selected text. | Already present in `authoring.tsx`'s `pourOver`, backed by `links.ts`; ordinary paste and image paste keep their paths. Covered in `e2e/compose-pwa.spec.ts`. | Extend oracle coverage of this existing feature. Do not build a second paste feature. |
| Safe emitted links | The Markdown grammar gives brackets, backslashes and destination parentheses meaning. A source wrapper alone cannot establish the intended rendered link. | Run: completing keyboard-created `[a]b]()` with `https://example.com/a)` yields broken link markup. The existing paste helper emits escaped label text and `%29` in the destination correctly. Recognition also differs: `links.isUrl` accepts uppercase schemes and surrounding whitespace; `formatEdit` does not. | Propose a rendered-link law and align completed-link insertion paths. Preserve the distinction between an unfinished keyboard placeholder and a completed link. URL recognition/escaping changes need an explicit law delta. |
| Enter on a nonempty list item | CodeMirror's [`insertNewlineContinueMarkup`](https://github.com/codemirror/lang-markdown/blob/8f73fd5013a1aaa3d3319f9165fff3100d159124/src/commands.ts#L98), All in One's [`onEnterKey`](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/listEditing.ts#L27), and EasyMDE's [Enter binding](https://github.com/Ionaru/easy-markdown-editor/blob/a48434196c8cfbfb2cae708390a26aed527cbf8c/src/js/easymde.js#L2132) continue list markup. Ordered-list numbering policies have configurable details. | Run: plain Enter is not a structural command. The textarea inserts a newline without a new list marker. | High-value candidate port: continue bullets and ordered markers with correct indentation; reset task checkboxes if task lists are later supported. |
| Enter on an empty item; Backspace after a marker | CodeMirror exits a markup level; All in One removes/outdents an empty item and has a dedicated [Backspace handler](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/listEditing.ts#L205). Exact empty-second-item behavior differs in CodeMirror's configurable tight/loose list handling. | These keys are left to native textarea editing. | Port together with continuation, so the writer can leave the list without manually deleting the generated marker. Do not copy CodeMirror's loose-list policy without a product decision. |
| Blockquote continuation/exit | CodeMirror and All in One continue `> ` on Enter and have a way to leave an empty quote. | There is no general Markdown blockquote continuation handler. Studio's blyg quote/transclusion tools are separate authoring operations. | Useful alongside list Enter support. Keep ordinary Markdown blockquotes distinct from protocol transclusion. |
| Tab/Shift+Tab on list lines | EasyMDE delegates to CodeMirror indentation. All in One supports [adaptive indentation](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/listEditing.ts#L260) based on preceding marker width. | Studio moves whole selected list lines; the adopted repair will account for long numeric parents. It deliberately declines off-list Tab so focus can move. | Preserve the web-form focus behavior. Test that emitted indentation really nests under the parent, not only that spaces were inserted. |
| Tab outside a list | EasyMDE inserts indentation; All in One falls back to VS Code's Tab command. These are full editor surfaces, not equivalent to a web form. | Native Tab focus navigation is an explicit Studio behavior. | No consensus requiring a port. Keep keyboard accessibility unless a deliberate editor-mode feature changes the contract. |
| Selection ending at next line's start | All in One's indentation code excludes the next line when the end column is zero. | Studio explicitly promises the same. Review has identified missing document-start/initial-LF coverage. | Keep as a reusable whole-line selection law across every line-oriented command. |
| Shift+Enter | Markdown source editors differ. All in One's Shift+Enter [takes its normal newline path](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/listEditing.ts#L40); rendered meaning also depends on the renderer's soft-break policy. | Studio deliberately writes a visible backslash hard break in prose and an ordinary newline in code/blank lines. Closing-fence preservation is adopted. | Keep Studio's adopted hard-break behavior. There is no cross-editor source-edit consensus that overrides it. Check rendered paragraph/code structure. |
| Undo, input and selection | GitHub [`insertText`](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L463) attempts native insertion, verifies it, and falls back on failure. All in One uses VS Code edit transactions. | Studio uses native insertion/deletion plus a `setRangeText` and bubbling-input fallback, then restores the selection. Real undo already has Playwright coverage. | Keep real-browser receiving checks. A fake command returning true is not proof that the browser edited text, preserved undo, or normalized newlines as expected. |
| Formula command | All in One has [separate math-state cycling](https://github.com/yzhang-gh/vscode-markdown/blob/066996a8d053f0f8d69978663a41222417b352a8/src/formatting.ts#L97). GitHub's inspected toolbar and EasyMDE's core command set do not establish a shared formula-toolbar convention. | Studio has its own inline/display selection rule; existing display preservation is now adopted. | Follow the adopted rule and Studio's math parser. Do not infer a universal formula toggle from one extension. |

## Candidate oracle additions

These are testing directions. Where they require a new behavior rather than stronger enforcement of an adopted law, agree on that law before encoding an expected result.

| Priority | Candidate | Inputs and observations that matter |
|---|---|---|
| High | Every command through the real keyboard handler | Independent selection endpoints, empty caret, partial/whole text, document edges, selected LF, surrogate boundaries, all platform/modifier masks, IME and already-handled events. Compare returned content and both selection endpoints at each command. |
| High | Command sequences | Generate type → format → format-other-style → toggle → undo/redo sequences. Use the returned selection as the next command's input. Observe after every step; final text can conceal a wrong intermediate caret. Preserve the editor's current freedom about valid delimiter spelling. |
| High | Rendered literal-code and nesting laws | Backtick/tilde runs, fence-like content, fence info, closing lines, CR/LF, leading spaces, Unicode closer tails; parent marker widths around 9/10, 99/100 and the nine-digit limit; blank/mixed selected lines. Observe parser tokens and rendered structure as well as source. |
| High | Completed-link rendering across paths | Arbitrary label brackets/backslashes, URL parentheses, query/fragment data, Unicode and scheme case; clipboard URL vs selected URL vs typed URL completion. Check one anchor with the intended label and destination. Treat tracker removal as a separately sourced policy. |
| High | Browser-host handoff | A small receiving driver in Chromium and, where supported, WebKit/Firefox: CR/CRLF normalization, selection clamping, native command returns false/throws/is absent, input delivery, and undo/redo. Distinguish the host-supplied premise from what Studio promises. |
| Medium | Formatting around existing markup | Star/underscore mixtures, code spans, link labels and destinations, escaped markers, intraword punctuation, blank-only selections. First choose where shortcuts should be syntax-aware; raw source wrapping and formatting the enclosing Markdown node are different contracts. |
| Medium | Toolbar and keyboard parity | Invoke the same accepted edit through toolbar, composer, full editor and quick editor. Check focus return, selection, scroll and onChange-visible state. Keep unsupported actions and expected no-ops explicit. |
| Medium | Accessibility behavior | Tab off a list, Shift+Tab navigation, toolbar keyboard activation, disabled/read-only controls, focus view, picker precedence and touch toolbar selection retention. GitHub's [toolbar arrow/Home/End navigation](https://github.com/github/markdown-toolbar-element/blob/2f5552a16fc561e6caecae4a1be654b8742f83f7/src/index.ts#L404) is a useful reference if Studio adopts a toolbar role and roving tabindex. |
| After adoption | Smart Enter/Backspace families | Nested lists and quotes, empty/nonempty item, split in middle/end, selected text, existing following items, ordered marker width, explicit nonsequential numbering, task checkbox states, code/HTML contexts, and exiting one level. |

The current code-formatting oracle work already covers parts of this table. The table identifies useful dimensions and receiving witnesses; it does not assert that each item is currently absent. In particular, the retained end-to-end suites already cover basic undo, keyboard delivery, pane/focus state, URL-over-selection paste, and image insertion.

## Missing common behavior worth considering

The order below favors everyday writing and reuse of the current textarea/edit architecture. Effort is relative, not a delivery estimate.

| Order | Candidate port | Evidence of common use | Expected value / effort | Scope to decide |
|---|---|---|---|---|
| 1 | Inline-code command, with an accessible toolbar action | GitHub, EasyMDE, All in One | High / small–medium | Choose a shortcut that avoids browser/OS conflicts; handle embedded backticks and surrounding backticks/spaces by a rendered literal-code law. Keep the existing code-block button. |
| 2 | Enter continues lists; empty Enter exits or outdents | CodeMirror, EasyMDE, All in One | High / medium | Bullet/number policy, preserving intentional numbering, split selections and nesting. Implement continuation and exit as one coherent feature. |
| 3 | Completed-link consistency using the existing escaping helpers | Studio already has the needed paste-side machinery; the same rendered link should work regardless of insertion path | High / small–medium | Reconcile placeholder editing with completed-link insertion; do not silently change URL recognition or tracker policy. |
| 4 | Word-at-caret emphasis | GitHub, All in One | Medium–high / small–medium | This changes the current empty-pair-at-caret contract. Define Unicode/punctuation word boundaries and caret preservation before porting. |
| 5 | Backspace removes/outdents list markup; blockquote continuation/exit | CodeMirror, All in One | Medium / medium | Interaction with native deletion, task checkboxes, selected ranges and code. Best shipped with smart Enter. |
| 6 | Basic heading, blockquote and new-list toolbar commands | GitHub and EasyMDE; All in One exposes corresponding commands | Medium / small–medium | Line-oriented transformations and repeated toggles; first/last partial lines; preserve blank lines. This makes standard Markdown easier on touch keyboards. |
| 7 | Strikethrough; task-list insertion if rendering support is chosen | GitHub, EasyMDE, All in One | Medium / small for strikethrough, medium for task lists | Task insertion alone is not enough: first verify desired rendered checkbox behavior. The inspected Studio renderer has no task-list plugin. |
| 8 | Remove an existing fenced/indented code wrapper | EasyMDE; selection-wrapper removal in GitHub | Medium / medium | Language info, partial selections, indented code, nested containers and preserving content. Less universal than inline code; specify before porting. |
| Later | Table generation/formatting, automatic pairs, whole-document reformatting, multiple cursors | Present in some full editors, not a shared baseline for a textarea | Variable / medium–large | These add substantial policy and interaction surface. They should not be bundled into the formatting-unit-test migration. |

There is no recommendation to replace the textarea with CodeMirror merely to obtain these features. The current pure `FormatEdit` boundary remains useful for independent models and small, predictable commands.

## Concrete probe evidence

The following observations were reproduced against the audit snapshot:

- Studio Bold at `wo|rd` returned `wo**|**rd`; GitHub's pinned command returned `**wo|rd**`.
- GitHub's selected ` word ` became ` **word** `; selected one space became ` ****`, with the caret between the stars.
- Studio's code-block command around `word` returned a fenced block; GitHub's generic code command around the same single-line selection returned a code span. This is a feature difference, not evidence that Studio's explicitly named code-block button is wrong.
- Studio Italic on the selected inner word of `_word_` returned `_*word*_`; GitHub's default underscore-italic command removed the surrounding underscores. GitHub's default bold command did not remove `__word__`, demonstrating why alternate-marker removal must not be called universal.
- Studio's keyboard-completed label `a]b` plus destination `https://example.com/a)` rendered as broken Markdown; `insertLink` escaped the label and destination and emitted a usable completed link.
- `structureKey` returned `null` for unmodified Enter and Backspace. The inspected editor integrations did not add another general Markdown list/quote continuation handler.

Reproduction scripts and full outputs remain in the task's temporary research directory, `/private/tmp/editor-conventions.fl09bE/`: `probe-github.cjs`, `probe-github.output`, `probe-repo.mts`, `probe-repo.output`, plus the exact downloaded upstream source and Studio source fingerprints. The repository probe runs with `node --import ./node_modules/tsx/dist/loader.mjs /private/tmp/editor-conventions.fl09bE/probe-repo.mts` from this worktree; the GitHub source-calculation probe runs with `node /private/tmp/editor-conventions.fl09bE/probe-github.cjs`.

This is a source-and-probe catalog, not a final oracle audit or a zero-gap claim. The current review repair pass owns that evidence. Proposed ports need accepted laws, red oracle witnesses where behavior changes, and receiving browser checks before their behavior is considered protected.
