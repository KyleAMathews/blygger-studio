# Editor feature laws for adoption

**Every proposal and numbered law below is UNADOPTED.** This document requests product decisions; it implements nothing and registers no oracle. Feature IDs F2–F5 come from [research next steps](editor-research-next-steps.md), not the earlier refactor's architecture IDs. **F1 inline code remains parked.** Existing emphasis, list indentation, formula, focus and source-preservation laws remain in force. Kyle Mathews (GitHub KyleAMathews) approved following main on 2026-11-21: native Enter/Shift+Enter insert ordinary newlines; the hard-break toolbar retains the separately adopted command law. No protocol, publishing, API or transclusion semantics change is proposed.

Prepared 2026-11-19 after rereading pinned `@tanstack/oracles@97a4e7a` design instructions. Sources are the [pinned editor catalog](editor-behavior-audit.md), current [research reconciliation](editor-research-next-steps.md), and 30 locally retained native-host probes. The catalog supports common editing directions; exact policies below are added recommendations, not a claim of universal editor agreement. Examples are proposed observations, not new probe results. `|` marks the caret; selections use `[from,to)` UTF-16 offsets.

## Shared proposed boundary

For every newly accepted formatting action, the immediate textarea source/range and React-received source must match its proposed edit; content outside its specified replacement is preserved, focus returns without scrolling, and one native Undo restores the prior source when the host supplied a genuine undoable edit. Fallback retains exact source/input/selection delivery without a new native-undo promise. Preserve the existing read-only, composing and already-handled gates; only an accepted keyboard edit prevents default. Modified Enter and picker precedence remain governed by existing dispatch, not silently redefined here.

Initial structural scope is explicit paragraph list/quote syntax with known container ancestry, outside fenced/indented code, raw HTML and display mathematics. Selected ranges may split a single paragraph line's body; multiple-line selections, existing code subtrees, lazy continuation lines and ambiguous container contexts retain native Enter/Backspace unless a later law adopts their transformation. These are proposed feature limits, not permission to narrow any existing oracle. The adoption decision must say whether this bounded first release is sufficient.

## F2 — smart list Enter, empty exit and Backspace (UNADOPTED)

**Recommendation:** ship continuation and escape together. CodeMirror, EasyMDE and Markdown All in One support the family; their exact loose-list and numbering policies differ. Preserve explicit bullet spelling (`-`, `+`, `*`) and ordered delimiter (`.` or `)`), visual nesting and surrounding source. Start with 1–9 digit ordered markers and explicit paragraph parents; task checkboxes await a renderer/product decision.

1. **Continue/split:** For every in-scope Enter whose ordered selection lies in one item's body, first delete the selection; when remaining body text is nonblank, split at that position into same-level siblings, insert LF plus a sibling marker and one space, and place the caret immediately after that prefix before the surviving right-hand text.
   Proposed observations: `- ab|cd` → `- ab\n- |cd`; selecting `bc` in `- abcd` produces `- a\n- |d`. Whitespace/content elsewhere is unchanged; an existing next sibling is not rewritten.
2. **Ordered successor:** For every continuation of an ordered item numbered `n`, write the canonical decimal successor `n+1` with the existing delimiter; at `999999999`, write `1` so the new marker stays supported, and preserve every pre-existing number, including deliberate gaps, repeated ones and leading zeros.
   Proposed observations: `09) x|` → `09) x\n10) |`; `7. x|\n42. y` gains `8. ` and retains `42. y`. The overflow restart and dropping padding on the new number are explicit policy additions.
3. **Empty Enter:** For every in-scope Enter leaving only spaces/tabs in the current item body, remove that body whitespace and exit exactly one list level without inserting another LF: a top-level item becomes an empty ordinary line; a nested item becomes an empty sibling of its parent, using that parent's marker spelling and successor rule.
   Proposed observations: `- |` → `|`; `- p\n  - |` → `- p\n- |`; `3. p\n   - |` → `3. p\n4. |`. This also defines Enter after selecting the entire body. Items with following descendants are outside this initial escape rule.
4. **Marker Backspace:** For every collapsed Backspace immediately after an in-scope item prefix, keep body text and source on other lines intact while converting a top-level item to ordinary text or a nested item to a sibling of its parent using the preceding exit policy; the caret stays before its body.
   Proposed observation: `- |word` → `|word`, without joining the previous line. Backspace within body text or with a noncollapsed selection follows native deletion.
5. **Container preservation:** For every accepted continuation or one-level escape, preserve remaining quote/list ancestors and emit indentation that renders at the intended sibling depth, including tabs, wide parent numbers and 1–4-column marker padding; space/tab indentation spelling is free where the required markers, preserved body text, final selection and rendered ancestry agree.

**Compatibility/cost:** ordinary Enter/Backspace become semantic edits at these positions; intentional numbering is preserved but newly generated markers may differ. Container parsing, empty-item ancestry and selection geometry need independent models and browser receiving coverage. Loose-list conversion, renumbering following siblings, automatic task resets and arbitrary existing subtrees are not bundled.

**Human adoption choices:** accept the five rules and bounded first release; confirm successor numbering/overflow and one-level parent-style exit, or choose literal `1` markers and/or native nested escape instead. Confirm whether selection of the whole body should invoke empty exit. These choices cannot be inferred from “stock standard.”

## F3 — safe keyboard-created completed links (UNADOPTED)

**Recommendation:** make commitment explicit. The research proved that raw keyboard placeholders can produce broken Markdown for label `a]b` and URL `https://example.com/a)`, while completed-link insertion handles them. It did not establish a universal source-editor “commit” keystroke. Prefer a familiar Insert link sheet for Cmd/Ctrl+K and the toolbar, with editable plain-text label and destination; keep raw Markdown typing literal. This deliberately replaces the current keyboard placeholder interaction and therefore needs a law delta.

1. **Open without editing:** For every link command over ordinary selected text, open a link sheet seeded with that exact label; for a selected HTTP(S) URL recognized after trimming surrounding whitespace and matching scheme case-insensitively, seed destination instead and focus the label field; otherwise focus destination, leaving source/range unchanged until commitment.
2. **Explicit commitment:** For every sheet with a nonempty label and valid HTTP(S) destination, Insert or unmodified Enter in a single-line field commits one completed link at the captured selection and closes the sheet; source outside that selection is unchanged and the editor caret follows the inserted link.
3. **Rendered intent:** For every committed link, independently render one anchor whose visible text equals the literal label and whose destination equals the trimmed URL's established browser URL projection subject to the already adopted tracker projection, preserving all other query/fragment data; bracket/backslash/entity-looking labels and destination parentheses must not create extra markup or anchors.
4. **Cancel/invalid:** For every Escape or Cancel before commitment, leave the current editor source untouched and return focus without scrolling; restore the captured range only if source is unchanged, otherwise retain the current editor range; for invalid/empty fields, keep the sheet open with field feedback and do not modify source.
5. **Stale selection:** For every source change while the sheet is open, disable commitment and require reopening at a fresh selection, preventing stale offsets from overwriting newer text.

**Compatibility/cost:** replaces `[selected]()` plus an empty-field source selection with a form and explicit transaction; adds focus, cancel, validation and stale-source behavior. Existing paste/clipboard helper policies remain separate. Editing an arbitrary existing Markdown link, relative URLs, empty labels, titles, multiline labels and unsafe schemes require separate laws; no silent parser rewrite on blur or a typed `)` is proposed.

**Human adoption choices:** accept sheet-based keyboard/toolbar commitment and literal labels, or retain raw placeholders and design a separate explicit completion action. The alternate preserves current interaction but needs placeholder identity, range tracking, cancellation and a discoverable commit gesture; closing punctuation alone cannot reliably identify intended completion. Confirm HTTP(S)-only initial scope and unchanged tracker policy.

## F4 — heading, ordinary quote and new-list tools (UNADOPTED)

**Recommendation:** accessible toolbar actions for Heading 1–6, Quote, Bulleted list and Numbered list; select levels explicitly rather than cycle hidden states. These are ordinary Markdown controls, separate from Blygger quotation/transclusion actions. GitHub/EasyMDE/Markdown All in One support the direction; the exact toggles below are proposed choices.

1. **Affected lines and atomic eligibility:** For every tool invocation, first collect the complete physical lines touched by the saved selection, excluding a final line touched only at its initial offset; if any affected line belongs to an excluded context or any affected nonblank line is outside that chosen tool's domain below, refuse the whole transformation without a source edit or tool-generated input, retain the saved range and return editor focus without scrolling; otherwise transform all affected nonblank lines together, preserve blank lines in a noncollapsed selection, and insert the chosen prefix on a collapsed eligible blank line with caret after it.
2. **Heading level:** For every affected ordinary paragraph or ATX heading line, set exactly the requested 1–6 leading `#` markers plus one space, replacing an existing ATX prefix; if all nonblank affected lines already have that level, remove their ATX prefixes, preserving content and existing closing text.
3. **Quote toggle:** For every affected paragraph/explicit quote line, if all nonblank lines have an explicit outer quote prefix remove exactly one such level; otherwise add `> ` only to lines lacking that outer prefix, retaining existing quote depth on the others.
4. **List toggle:** For every affected ordinary/list paragraph line without descendants, if all lines already have the requested list kind remove one marker/padding prefix per line; otherwise replace existing list prefixes or add new prefixes using `- ` or sequential `1. `, `2. `, … at that context's level, retaining body text and indentation.
5. **Selection mapping:** For every tool edit, map each saved endpoint to the same body-text offset after changed prefixes; an endpoint inside a replaced prefix maps to its new body start, and a collapsed blank-line caret follows the inserted prefix; return focus without scroll and expose the same result through click, Enter and Space activation.

**Compatibility/cost:** adds toolbar surface and makes repeated activation a toggle. New numbered-list conversion deliberately normalizes selected item numbers; F2 continuation deliberately preserves existing numbers. Classify actual blocks rather than just punctuation: literal `#word` and escaped markers remain ordinary paragraph text, so adding a prefix preserves those characters; thematic breaks, code and setext headings are ineligible. Conversions between headings, quotes and lists, nested descendants and selection-in-code behavior stay outside the first tools' domain. Selecting all of `text\n---` (a setext heading) then Heading 1 refuses atomically; selecting `text\nword` accepts both paragraph lines. A paragraph-plus-code or paragraph-plus-thematic-break selection also refuses as a whole; it never silently formats only eligible lines. Blank lines are the sole specified skipped lines, and an all-blank noncollapsed selection makes no edit.

**Human adoption choices:** accept explicit H1–H6 and the atomic-refusal/toggle/blank-line/endpoint rules; confirm whether mixed quoted/unquoted selections should homogenize one outer level as above or add a level to every line. Confirm default `-` and sequential `1.` spelling, plus the limited conversion domain.

## F5 — quote Enter and empty exit (UNADOPTED)

**Recommendation:** continue explicit ordinary quote prefixes and leave one level at a time, following CodeMirror/Markdown All in One's common direction. Preserve Studio's 2026-11-21 native Shift+Enter ordinary-newline rule and its separate hard-break toolbar command.

1. **Continue:** For every in-scope Enter inside an explicitly quoted paragraph line, first delete a same-line body selection; only when the remaining body is nonblank, split at the resulting caret and prefix the new line with the same quote depth in canonical `> ` spelling, preserve both remaining bodies and put the caret after the new prefix.
   Proposed observation: `> ab|cd` → `> ab\n> |cd`; at two levels, the new line starts `> > `.
2. **Empty exit:** For every Enter on an explicit quote line whose remaining body is only spaces/tabs, remove that whitespace and exactly the innermost quote level without inserting LF; preserve outer ancestors and caret position at the remaining prefix's end.
   Proposed observations: `> |` → `|`; `> > |` → `> |`. Selecting the entire body first uses the same rule.
3. **List precedence:** For every Enter in a list paragraph inside a quote, apply F2 to the deepest list item while retaining all quote ancestors; an empty nested list leaves one list level before a later Enter can remove a quote level.

**Compatibility/cost:** ordinary Enter now inserts quote markup in these contexts. Existing source with compact `>>` prefixes may gain canonical spaces on the new line; existing lines keep their spelling. Lazy quote continuation, quotes inside list items, multi-line selections, raw HTML, fenced/indented code and display math require additional rules before automatic continuation.

**Human adoption choices:** accept one-level exit and list-first precedence, or choose ordinary native Enter in mixed list/quote containers initially. Confirm canonical new-line prefix spelling and the bounded explicit-prefix domain.

## U2 — native-command recovery (UNADOPTED)

**Recommendation:** adopt bounded synchronous recovery first. The completed probes show normal Chromium/Firefox native insertion and forced-refusal fallback working; injected absence/throw-before-mutation propagate errors, and injected success without mutation misses a nontrivial replacement. None establishes actual browser dishonesty or a general rollback policy. GitHub's pinned insertion helper supports verifying the requested result before trusting a success flag.

**Decision checkpoint and host premise:** let `S` be the initial textarea value and `R` the original-source splice with inserted CR/CRLF normalized to LF; an unchanged requested edit means exactly `R === S`, including replacement by identical text. Inspect source and input receipts synchronously when the native attempt returns or throws, before fallback/final-selection work. A receipt is an `input` targeted at this textarea while that attempt is on the stack, recorded with its bubbling flag and source at dispatch; “expected input receipt” for a changed native result means at least one bubbling receipt observing `R` and no receipt observing a different source. Initial scope assumes command source/input effects finish synchronously; absence of a synchronous receipt does not prove no delayed receipt can arrive. Missing API uses the same checkpoint with no invocation.

1. **Recover unchanged-at-return failures:** For every valid edit within that synchronous-host premise, if source is still `S` and no input receipt exists at the decision checkpoint, and the API is unavailable, refuses, throws, or claims success while `R !== S`, deliver `R` and the requested clamped selection through fallback, emit one bubbling fallback input and exactly one explicit synthetic textarea `selectionchange` after final selection, and return normally with focus preserved without scrolling.
2. **Recognize success/no-op:** For every native success observing `R` with its expected input receipt when `R !== S`, or observing unchanged `S` with no receipt observing a different source when `R === S`, preserve that result and its native undo history without fallback; set the requested final selection and emit exactly one explicit synthetic textarea `selectionchange` afterwards, allowing additional native queued selection events without an exact total-event-count promise.
3. **Preserve bypass:** For every deliberately bypassed native command, including intra-grapheme ranges, perform the existing exact fallback without consulting or requiring a native API; absence and bypass remain distinct host histories.

**Compatibility/cost:** broadens the current truthful-native/refusal host contract and prevents uncaught unchanged-at-return failures within the synchronous-host premise. It adds capability/exception/postcondition handling and precise source/input observations; it does not promise native Undo after fallback. Snapshot equality does not establish that no transient mutation occurred. CR/CRLF normalization, surrogate boundaries and unchanged requested edits must retain their existing neighbors. Fallback's explicit synthetic selectionchange also allows additional native queued selection events.

**Human adoption choices:** accept only these bounded synchronous recovery promises now, then explore delayed source/input delivery, changed-source-without-input, exceptions/wrong results after partial mutation, and incorrect emitted input before deciding overwrite/rollback/public-error behavior. Those histories remain unresolved; the checkpoint does not infer that no future input will arrive, and the current probes do not justify their policies. Do not replay original offsets after partial mutation or infer safe React recovery from final DOM alone; an intermediate wrong input is publicly observable.

## Proposed oracle design and adoption order

The design-grammar trigger fires: these proposals add more than five laws to structural editing and introduce pending link state. Preservation relation is **named existing laws at every source/range/input/undo checkpoint**, with the proposed behavioral revisions above shown separately. No model was changed, so there is no measured refactor comparison or new runtime evidence.

Reduced parts: **source + saved range** preserve untouched content and selection; **annotated container ancestry/content columns** decide split/exit depth; **action** selects Enter/Backspace/tool intent; **pending link draft + captured source revision** distinguish commit, cancellation and stale selection; **host outcome/input receipt** distinguishes native success, refusal, bypass and proposed recovery. Each part has a witness above: mid-body split, nested empty exit, cross-line selection, source change during a link draft, and unchanged successful no-op.

Prefer pure annotated edit functions for F2/F4/F5, a small explicit closed/open link transition table for F3, and a separate host transaction model for U2; use independent rendered ancestry/anchor observations where source spelling is free. An adjacent form is one editor-wide transition model carrying all pending interaction state: it unifies lifecycle handling but costs a larger legality surface and risks duplicating parser/host logic. Another is pure source tools plus a separate completion action preserving placeholders: it avoids a new sheet but adds identity/range tracking and commit discovery. None is implemented or adopted.

After human adoption, first probe newly chosen boundaries, then write or extend generated **browser oracles only**, including constructed edge histories, real React receipt, intermediate source/ranges, bound calibrations, original-defect challenges and law-preserving neighbors; obtain registered RED before production behavior changes. Keep old-loss observations and the current campaign freeze intact. Suggested decision order: bounded U2 recovery, F2 as a family, F3 interaction choice, F4 tools, then F5 overlaps. No proposal here closes existing framework questions or authorizes test deletion.
