# Formatting oracle refactor plan

The design grammar points to shared document/edit plumbing and reusable independent command models, with separate rendering and textarea delivery checks. The initial six files register 18 properties; those properties overlap in useful ways. The first refactor should remove duplicated expectations and infrastructure while preserving those intersections.

The [model](editor-oracle-design/model.md), [evidence](editor-oracle-design/evidence.md) and [process](editor-oracle-design/process.md) contain the frozen extraction, alternatives, ablations, source fingerprints and limits. The approved F2 architecture is now implemented by the browser execution revision below; the numbered proposal preserves the original migration plan.

1. **Freeze the migration contract.** Retain all 91 old assertions as named, constructed witnesses, including exact document contexts and both selection endpoints. Keep the restored bullet/existing-list rendering, first-child ancestry, default code-wrapper syntax and empty-block caret membership. Keep every existing seed, calibration and authored challenge. The old unit file stays until the refactor passes another loss audit.

2. **Extract a small test-side core.** Share UTF-16 source partitions, selection construction, edit application/outcome projection and trace/error recording. Keep three semantic model families: text commands, list structure and textarea transactions. Within text commands, emphasis, links, formulas, code blocks and breaks retain their own rules. Keep authorities, limits, ownership, reach and calibrations beside each `oracleProperty`; avoid a new generic testing DSL.

3. **Reuse full command expectations across entry points.** Move semantic models and histories into test-free companion modules, then let direct-command and keyboard drivers consume them. Replace the handler's current simplified formatting expectations. It must still execute the real handler and independently verify forwarding, default prevention, picker/IME/read-only gates and delivery effects. Retain actual renderer checks and real-browser receiving tests to counter shared-model mistakes.

4. **Add bounded composition and receiving coverage.** From the [editor audit](editor-behavior-audit.md), carry forward command sequences using each returned selection, intermediate checkpoints, deliberately generated markup/Unicode boundaries, toolbar/keyboard parity and coverage of the existing URL-over-selection paste path. Keep browser undo/redo, input delivery, focus and CR/CRLF normalization in receiving checks. Probe native-command exceptions/absence before deciding whether they imply a new promise. Do not assert universal toggle round trips.

5. **Queue editor improvements with explicit law changes.** The audit's first candidates are a separate inline-code command; list continuation plus empty-item exit; and consistent completed-link escaping across keyboard/paste paths. Specify literal rendering, selection, numbering and code-context rules before implementation. Word-at-caret emphasis changes the current empty-pair behavior and needs a separate decision. Backspace/list/blockquote continuation, alternate markers, heading/quote/list toolbar actions, strikethrough, task lists and code unwrapping remain later proposals. Task lists require a renderer decision. Tables, automatic pairs and broader editor replacement stay outside this migration.

6. **Validate each extraction before deleting tests.** Compare allowed outcomes in both directions on unchanged histories; preserve explicit whole-line range promises while allowing incidental replacement spans where the contract permits them. Run `oracle-gaps` after each model extraction, retain kills for shared mutant keys, challenge the new seams, rerun typechecking and scoped browser tests, then independently review and repeat the old-test loss audit. Do not lower runs or turn fixed witnesses into chance coverage to make the refactor pass.

The alternatives are a smaller helper-only extraction, which leaves semantic duplication in place, or a complete editor action-state model, which adds substantial legality and host complexity. F2 offers a bounded first step; a small sequence driver can follow without requiring the full editor model.

The restored baseline currently passes 2,454 checks and kills 359/361 mutants, including all 21 authored challenges, with zero unowned units. Two emphasis warnings remain open with framework evidence; they are not kills. This design pass establishes neither zero gaps nor cross-browser equivalence. The catalog informs the proposed extensions and is not held-out validation.

## Browser execution revision (2026-11-18)

Kyle clarified that formatting must be covered only by oracles, and that production formatting must execute in a real browser. This supersedes the earlier references to fixed Playwright complements. F2's shared independent models remain; Chromium now runs the production formatter, native textarea transactions and actual React app histories. The Node-only pinned package coordinates generated histories and judges their observations.

The Vite post-transform captures the exact oracle-gaps-instrumented module as a browser factory. The actual SPA's test bundle delegates only its formatting dependency to that module. React listeners, toolbar callbacks, preview requests, autosave and native input remain production code. Browser instrumentation replays reach/infection/work records to the pinned capture; authored and automatic mutation challenges verify this path. This test seam is outside shipped production bundles.

Generated receiving histories replace the two fixed formatting Playwright files. They retain composer undo→kind-switch persistence, loaded whole-document editor/quick-editor selection, same-item editor→quick-editor transition, native Tab focus navigation, nested-list preview, verse preview, and desktop/mobile toolbar/toast behavior. Old files remain until the final loss audit and execution evidence pass. Every new test registration is an oracle; no fixed expected-answer test is renamed to look like one.

Native-browser exploration additionally exposed collapsed-empty native deletion, native grapheme-range snapping, and Unicode key folding. These are strengthened histories of the adopted exact-replacement and ASCII shortcut laws, with RED evidence before each repair. The editor-feature proposals in step5 remain proposals.


## Native-newline mapping revision (2026-11-21)

Kyle Mathews (GitHub KyleAMathews) approved following main: Enter and Shift+Enter retain native ordinary-newline editing, while the hard-break toolbar retains `breakEdit`. This changes the keyboard command mapping, not the independent hard-break command's source/range/caret/rendered laws. Every old verse/mixed history is retained through the real toolbar; native newline receives separate real-browser histories, trusted key receipt, selected-source replacement, caret/focus, native undo/redo and full-editor ordinary-paragraph checks. Exact old fixed/random budgets, seeds and calibrations remain. The design keeps separate `newline` keyboard and `break` toolbar intents because their continuation produces distinct source and rendered breaks. See the [versioned law delta](editor-oracle-design/native-newline-law-delta.md); current-main legacy tests are retained pending fresh registered evidence and loss review.
