## Preservation and boundary

The extraction keeps every historical input, output/selection checkpoint, fixed seed, constructed witness and authored challenge. The browser revision strengthens the same adopted formatting laws through native DOM and actual React receivers. Source edits execute only in Chromium. Models and checks execute in the package's Node runner; the actual preview is produced by the disposable application's Worker and consumed in Chromium.

The shared core contains document geometry and observations. Text commands expose independent semantic edits; direct-command and keyboard models reuse them. Lists retain their annotated row/tree model. Textarea expectations allow native success, native refusal with fallback, and direct exact fallback. They do not repeat production's grapheme classifier. App histories require native undo on ordinary user selections, distinguishing an always-fallback implementation through public behavior.

Design-grammar triggers: model extraction/substitution, more than five formatting obligations, and the native-host boundary. The approved F2 design is retained. The new browser receiving model is a bounded linear action history; its state is source, selection, semantic delimiter count, and undo/redo records. Source and selection distinguish the next formatting action; delimiter count predicts selected versus external style; undo/redo records distinguish later restoration. No formal model checker ran.

