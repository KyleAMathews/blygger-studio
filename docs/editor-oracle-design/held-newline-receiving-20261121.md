# Native newline receiving at editor regions

The new `editor-browser-held-newline` property strengthens the adopted editor
preservation promises at real hidden and shown paragraphs. Its authority is
`docs/extensions.md`, Editor regions: the draft always contains the whole text;
replacement surrounding a hidden cut puts the held region after replacement;
shown overlap refuses with feedback; an exact region edge accepts. Native
Enter/Shift+Enter retain the approved ordinary-LF rule. No production code was
changed for this addition, and no further old tests were removed.

The design grammar trigger is the existing boundary's more than five laws.
The preservation relation is **named adopted laws**, at pre-key delivery,
immediate post-key source/caret/focus, region feedback and explicit Save
completion. Undo after refusal, refusal caret geometry and exact native input
event counts remain unconstrained. The existing mixed model and comparisons
judge accepted visible edits without changes.

| Part | Job and distinguishing witness |
|---|---|
| Left and held words | Vary content, length and Unicode boundaries without copying region parsing; astral code points keep real selections grapheme-safe. |
| Hidden cut | Replacing all shown source must save LF before the held paragraph; a late caret correction can leave visible LF correct while moving the paragraph. |
| Shown overlap | Selection includes the final held code point and following suffix; refusal must preserve the whole displayed and saved source. |
| Exact edge | Move the same selection start just beyond the held paragraph; an overbroad protection rule now rejects a legal edit. |
| Key and viewport | Both native Enter forms and both viewport profiles have constructed receiving histories. |
| Save completion | Trusted click and actual busy lifetime settle before full-item GET, so a later edit cannot repair a stale React value. |

The reduced model uses explicit input segments for full-source expectations and
the unchanged mixed model for accepted visible changes. A unified segment-edit
state machine would duplicate the region rebase mechanism; three independent
LF models would duplicate the existing mixed oracle. Neither alternative is
needed for this one-key receiving boundary. This is a new receiving route,
not a refactor of the mixed model or a claim of region-scanner coverage.

The arbitrary varies nonempty ASCII, Greek and astral words up to eight code
points, three region modes, both keys and viewports. All 12 mode/key/viewport
intersections are constructed; fixed seed `20261118` and 25 generated histories
remain. An empty held word is explicitly rejected by this segment grammar.
All existing session histories, seeds, budgets and comparisons are preserved;
18 additional constructions force refused, throwing and missing native commands
on each surface and both Enter keys. These do not establish native undo with
the command unavailable.

The provider is the actual compiled `regions-example`, enabled through the
real settings contract before full-editor navigation. The driver seeds full
source through the API and never fills the hidden textarea. Show's scheduled

for model-desired output. Complete native input receipts remain diagnostic;
their exact count has no new acceptance rule.
